# 新题型人工证据模板（2026-11-12）

> 这不是验收通过记录。没有真实执行者、真实设备与原始记录时，本文件所有格子都是
> **NOT_RUN**。模板只规定"要记录什么"，不产生数据；也不得把空表或 agent 代填读成通过。
> 与 `docs/MANUAL-ACCEPTANCE.md` 的 `manual-evidence.mjs` 配合使用：原始记录放在仓库外
> 或 `release-artifacts/`（已忽略），证据 JSON 用当前源码快照绑定。

## 1. 范围

`tile-rotation-v1`、`symbol-path-v1`、`crowd-find-v1`、`visual-rank-v1`、
`progressive-target-v1`、`shell-track-v1`、`silhouette-assembly-v1`，以及
`shape-grid-v1` 的 positive/negative 两种指令。

## 2. 每题型的最低执行矩阵

每格 5 次；**不得合并不同输入方式或语言**，也不得用自动答案表代替真人操作。

| 维度 | 次数 | 记录字段 |
|---|---|---|
| 桌面 pointer | 5 | 完成时间（秒）、是否意外失败、失败原因、刷新次数 |
| 桌面 keyboard-only | 5 | 同上；记录 Tab 顺序、方向键/Enter/Space/Backspace 是否够用 |
| 真实移动设备（触摸） | 5 | 设备型号、OS、浏览器版本、视口宽高、是否 320 CSS px 附近、是否横向滚动 |
| 中文界面 | 5 | 指令是否一看就懂；negative 题单独记录否定词是否被注意到 |
| 英文界面 | 5 | 同上，并与中文分开统计 |

`shape-grid-v1` 的 positive 与 negative 必须**分开**各做一轮；negative 至少覆盖
kind 与 category 两种句式。`shell-track-v1` 还必须记录 `prefers-reduced-motion` 开启时
页面是否明确提示换题（不要求完成动画）。

## 4. 产品目标（只标 `[目标]`，不是实测结论）

- 中位完成时间 ≤20 秒；P95 ≤45 秒；
- 每组 5 次中"意外失败"≤1 次；
- 不出现横向滚动；
- 不出现无法恢复的 focus trap；
- 不依赖颜色、声音、摄像头或精确高速运动；
- 五次样本不外推为总体统计，也不作为抗 AI/抗 OCR 证据。

## 5. 结论写法

- 只有真实执行并留下原始记录 + 哈希，才可写 `PASS` 或 `FAIL`；
- 未执行写 `NOT_RUN`；
- 外部条件不足（缺设备/缺参与者/缺浏览器）写 `BLOCKED`；
- 不得写"PASS：某项未测"这类混合表达；不得用截图代替交互记录。
