# 低密度前端题型扩充设计

状态：设计候选，不代表当前 runtime 已实现。三个题型都必须先完成生成器、widget、真实浏览器和真机验收，再加入任何默认题池。

## 1. `memory-sequence-v1`

完整契约见 [`QUESTION-TYPE-MEMORY-SEQUENCE.md`](QUESTION-TYPE-MEMORY-SEQUENCE.md)。它使用服务端预渲染的高亮序列和低密度网格，答案为固定长度的 `sequence`。目标是替代移动端无法稳定命中的 6×6 路径题。

最低要求如下。

- 3×3 或 4×3 网格，触屏命中盒至少 44×44 CSS px。
- 观察阶段不下发序列，客户端不判断每一步。
- 支持点击、Tab、方向键、Space/Enter 和 Backspace 撤销。
- reduced-motion 下使用静态等价题或明确换题。
- 30 个固定 seed、Chromium/Firefox、320/375/414 真实 viewport、键盘和触屏全部有证据。

## 2. `drag-align-v1`

### 2.1 任务

用户将一个几何部件拖到匹配槽位。槽位是离散集合，成功答案是 `slot_id`，不上传浮点坐标。部件、槽位和干扰项全部由服务端程序化生成。

### 2.2 公开 payload

```json
{
  "kind": "drag-align",
  "answer_type": "select",
  "input_mode": "drag-align",
  "image_width": 480,
  "image_height": 300,
  "piece": {"x": 48, "y": 90, "w": 64, "h": 64},
  "slots": [
    {"id":"A", "x":300, "y":48, "w":64, "h":64},
    {"id":"B", "x":300, "y":140, "w":64, "h":64},
    {"id":"C", "x":300, "y":232, "w":64, "h":64}
  ],
  "prompt_zh": "把部件拖到形状完全匹配的槽位。",
  "prompt_en": "Drag the piece to the matching slot."
}
```

答案只允许 `v1:A` 这种离散槽位编码。目标匹配依据私有 verifier，公开 payload 不能包含正确槽位或可逆映射。

### 2.3 前端要求

- Pointer Events 使用 `setPointerCapture`，丢失 `pointerup` 时能安全取消。
- 键盘路径使用方向键移动焦点，Space 选择部件，方向键移动到槽位，Enter 放置。
- 触屏部件和槽位的命中盒至少 56×56 CSS px，视觉图形可以小于命中盒。
- 拖动时显示明确的抓取状态、目标槽位 hover 状态和放置成功状态。
- 不能把拖动轨迹上传为答案，最多记录有界的行为摘要。
- 320/375 CSS px 下改为上下布局，不能让部件和槽位缩成一排小目标。

### 2.4 验收

- 30 个 seed 的唯一匹配和私有 verifier 通过。
- 鼠标、触屏、键盘各 30 次完成率 100%。
- 丢失 pointerup、越界、取消、Undo、重复放置和 reset 各有回归测试。
- 触屏目标 56px，焦点环可见，200% 缩放没有重叠或横向溢出。
- 真实 Chromium/Firefox 和至少一台触屏设备完成验收后才能进入试点。

## 3. `semantic-select-v1`

### 3.1 任务

用户阅读一条短条件和 6–8 个文本选项，选择唯一满足条件的选项。它是可访问和低密度的补充题型，不是强安全题型，默认只在显式 accessibility 请求或低风险带使用。

### 3.2 安全边界

- 题面文本必须由服务端生成，答案不出现在字段名、选项 ID 或 URL 中。
- 选项使用随机公开 ID，服务端 verifier 只接受一个规范 ID。
- 题目避免文化常识、政治、品牌、医学和主观判断，避免把语言能力误当成真人证明。
- 单次随机猜测通过率、语言理解错误率和无障碍完成率分别报告。

### 3.3 前端要求

- 使用真正的 `radio` 语义或等价的 `aria-checked` 控件。
- 纯键盘可完成，屏幕阅读器能先读条件再读选项。
- 选项按钮至少 44px 高，中文和英文文本在 200% 缩放下不截断。
- 选项顺序、焦点环、选中状态和错误提示不能依赖颜色 alone。
- 不加载图片，不要求动画，不因为 reduced-motion 或低带宽降级。

### 3.4 验收

- 普通参与者首次通过率目标至少 85%，无障碍队列至少 75%。
- NVDA/VoiceOver、键盘、200% 缩放和 320px 内容宽度完成率 100%。
- 3 次随机猜测累计通过率必须记录，超过 10% 时只能作为低风险辅助通道。
- 不得把 `semantic-select-v1` 标成强安全题型或用它替代风险评分。

## 4. 共同发布门槛

三个题型共同遵守以下门槛。

1. 生成器、payload、verifier、widget 和答案规范化必须有版本化契约。
2. 公开数据不得含答案、目标索引、可逆 seed 或解法。
3. 工程测试、真实视觉测试、人工测试、无障碍测试和 M4 分开记录。
4. 任一真实 viewport 溢出、命中盒不足、键盘路径失败、过期状态错误或迟到响应污染，都保持 `FAIL`。
5. 工具、设备、Go runtime、Firefox 或真实参与者缺失时保持 `BLOCKED` 或 `NOT_RUN`。
6. 所有题型完成 `production_ready` 门槛前都保持 `experimental:true`。
